【共通テスト対策】アルゴリズム徹底解説

バブルソート（降順）のプログラムを読み解く

プログラムの全体像と実行結果

まず、今回解説するPythonプログラムの全体像を見てみましょう。このプログラムは、リスト（配列）`Time` に格納された数値を**大きい順（降順）**に並べ替えるものです。

Pythonコード

Time = [72,68,70,73,69,71,74,66,67,75,65,76]

# バブルソートによる降順ソート
for i in range(11, 0, -1):
    for j in range(0, i, 1):
        # 隣り合う要素を比較
        if Time[j] < Time[j+1]:
            # 要素を交換（スワップ）
            temp = Time[j]
            Time[j] = Time[j+1]
            Time[j+1] = temp

# 結果を出力
print(Time)

実行結果

このプログラムを実行すると、リストの中身が綺麗に並べ替えられ、以下のように出力されます。

[76, 75, 74, 73, 72, 71, 70, 69, 68, 67, 66, 65]

プログラムの1行ずつ徹底解説

プログラムが何をしているのか、パーツに分けて詳しく見ていきましょう。

1. データの準備

Time = [72,68,70,...]

まず、並べ替えたい12個の数値が入ったリスト（共通テストの疑似言語では「配列」）を`Time`という名前の変数に準備します。

2. 外側のループ（走査範囲の制御）

for i in range(11, 0, -1):

ここからが並べ替えの本体です。これは「二重ループ」の外側です。
`range(11, 0, -1)`は、変数 `i` の値を `11` からスタートし、`1` ずつ減らし、`1` になるまでループを繰り返す命令です。つまり、`i` は `11, 10, 9, ..., 1` と変化します。
このループは、比較する範囲を徐々に狭めていく役割を持ちます。

3. 内側のループ（隣同士の比較）

    for j in range(0, i, 1):

こちらが「二重ループ」の内側です。
`range(0, i, 1)`は、変数 `j` の値を `0` からスタートし、`1` ずつ増やし、`i-1` になるまで繰り返します。
例えば、外側の `i` が `11` のとき、`j` は `0, 1, ..., 10` と変化します。`i` が `10` のときは `j` は `0, 1, ..., 9` と変化します。
このループで、リストの要素を先頭から隣同士で比較していきます。

4. 条件分岐（順序の確認）

        if Time[j] < Time[j+1]:

`Time[j]`（左側の要素）と `Time[j+1]`（右隣の要素）の大きさを比較します。
もし「左側 ＜ 右側」なら、降順（大きい順）にしたいので、これは望ましくない順序です。この条件が満たされた（真/Trueになった）場合、次の「交換」処理が実行されます。

5. 交換（スワップ）処理

            temp = Time[j]
            Time[j] = Time[j+1]
            Time[j+1] = temp

2つの要素の値を入れ替える処理で、「スワップ」と呼ばれます。

  • 一時的な変数 `temp` に左側の値 (`Time[j]`) を避難させます。
  • 空になった左側の場所に、右側の値 (`Time[j+1]`) を入れます。
  • 右側の場所に、避難させておいた `temp` の値を入れます。
これにより、大きい方の値が左に移動します。

バブルソートの仕組みを図解

バブルソートは、隣り合う要素を比較して交換していくことを繰り返すことで、全体を整列させます。このプログラムの動きをステップごとに見てみましょう。

このアルゴリズムでは、内側のループが1周する（これを「1回のパス」と呼びます）ごとに、**その時点で最も小さい値が、比較範囲の右端に確定**します。泡が浮き上がる様子に似ていることから「バブルソート」と呼ばれます。

最初の状態

[72, 68, 70, 73, 69, 71, 74, 66, 67, 75, 65, 76]

1回目のパス (i = 11)

`j`が`0`から`10`まで動きます。隣同士を比較し、`左 < 右` なら交換します。

  • `j=0`: [72, 68] → 比較 (72 > 68) → 交換なし
  • `j=1`: [72, 68, 70] → 比較 (68 < 70) → 交換 → [72, 70, 68, ...]
  • `j=2`: [72, 70, 68, 73] → 比較 (68 < 73) → 交換 → [72, 70, 73, 68, ...]
  • ...この処理を最後まで繰り返します...

このパスが終わると、最も小さい値 `65` がリストの一番右端に移動して確定します。

1回目のパス終了後（のイメージ）

[..., 66, 65]

（※実際には他の要素も移動しますが、重要なのは一番小さい値 `65` が右端に確定することです）

2回目のパス (i = 10)

`j`が`0`から`9`まで動きます。比較範囲が右端の一つ手前までになります（`Time[11]`は既に最小値で確定済みのため）。このパスが終わると、2番目に小さい値 `66` が右から2番目に確定します。

2回目のパス終了後（のイメージ）

[..., 67, 66, 65]

以降のパス

この操作を `i` が `1` になるまで繰り返します。パスを重ねるごとに、比較範囲が狭まり、小さい順に右側から要素が確定していきます。

最終結果

全てのパスが終了すると、リスト全体が降順に並べ替えられます。

[76, 75, 74, 73, 72, 71, 70, 69, 68, 67, 66, 65]

共通テスト対策としての重要ポイント

このプログラムを通じて、共通テスト「情報Ⅰ」で問われる可能性のあるポイントを整理しましょう。

ポイント1：アルゴリズムの読解力

ループ変数がどのように変化するか、条件分岐が何を判定しているかを正確に追うことが最も重要です。

  • ループ範囲の確認: `i を N-1 から 1 まで`、`j を 0 から i-1 まで`という範囲をしっかり把握しましょう。
  • 条件分岐の向き: `A < B` を `A > B` に変えるとどうなるか？ → 昇順（小さい順）になります。この違いが結果にどう影響するかを問う問題は頻出です。

ポイント2：計算量

アルゴリズムの効率性を表す「計算量」は重要な概念です。バブルソートは、比較的効率の悪いアルゴリズムとして知られています。

  • 比較回数: 要素数を$N$とすると、比較回数は $\frac{N(N-1)}{2}$ 回です。今回の例では $N=12$ なので、$12 \times 11 / 2 = 66$ 回の比較が行われます。
  • オーダー記法: このような$N^2$に比例する計算量を $O(N^2)$（オーダーエヌ二乗）と表現します。
  • 特徴: 要素数が2倍になると、処理時間は約4倍になります。データ量が多い場合には非常に時間がかかるため、実用的な場面ではあまり使われません。
  • 他のソートとの比較: 選択ソート、挿入ソートも $O(N^2)$ の仲間です。より高速なマージソートやクイックソート（平均 $O(N \log N)$）との性能比較が問われることがあります。

ポイント3：共通テスト疑似言語(DNCL2)での表現

このPythonプログラムを、近年の共通テストで用いられる新しい疑似言語（DNCL2）の形式で記述すると以下のようになります。

// 手続きの定義 (DNCL2形式)
●手続き 降順バブルソート(配列 A)
  // 変数の宣言
  変数 i, j, temp は整数
  変数 N は整数
  N ← 配列Aの要素数

  // 外側ループ
  繰返し i を N-1 から 1 まで -1ずつ
    // 内側ループ
    繰返し j を 0 から i-1 まで 1ずつ
      // 比較と交換
      もし A[j] < A[j+1] なら
        temp ← A[j]
        A[j] ← A[j+1]
        A[j+1] ← temp
      判断終わり
    繰返し終わり
  繰返し終わり
  戻り値 A
●手続き終わり

// メイン処理
●手続き メイン()
  配列 Time ← {72,68,70,73,69,71,74,66,67,75,65,76}
  配列 結果配列
  結果配列 ← 降順バブルソート(Time)
  表示(結果配列)
●手続き終わり
